怎么做到的

浏览器算坐标，画板只当渲染后端

画板 API 只有「矩形 + 文字 + 连线」，没有排版能力。手算坐标就是盲画。 但 CSS 的 flex/grid 是成熟排版引擎 —— 让 puppeteer 把它算好的绝对坐标读出来，翻译成画板节点就行。

HTML 设计稿（Chrome 渲染）

翻译成画板后（飞书渲染）

两层分开画：有背景或边框的元素 → composite_shape；每个文本节点 → text_shape。因为画板的文字是节点属性、没有 padding 概念。 分层之后连内联加粗都能保住 —— 每个文本节点各自取父元素的样式。

画板 API 的坑（官方文档站查不到，全是试出来的）
  • border_width:"none" 是非法值 —— 无边框要用 border_style:"none" 且不传 width
  • border_style 只有 solid / dash / dot，没有 dotted
  • 连线的 arrow_style 在 start/end 里，放顶层会被静默忽略 —— 我因此收过一串假阳性
  • 箭头只有 none 和 line_arrow 两种，triangle 之类全非法
  • 画板只能追加，PATCH / PUT / DELETE 节点全是 404 —— 画错了只能删掉块重建
  • 画板字体比 Chrome 宽，文字框要留 14% 余量否则折行
  • download_as_image 按 ~2x 导出，别拿导出像素当画布单位

你问的第 5 件事

交互页面能不能塞进飞书文档

能。飞书文档有 iframe 块，我测了 8 种域名，API 层面全部接受。 但建得进去 ≠ 渲染得出来 —— 页面能不能显示，取决于对方站点的 X-Frame-Options。 这一页本身就是测试样本：它现在有公网地址，把地址塞进飞书 iframe 块就能验证。

node tools/preview.js       <whiteboard_id> <out.png>      # 画板回读自检

# 录 GIF
node tools/gif/record.js <scene.html> --out=x.gif --keep=6,30,66
